Working Principle

1. Update. Each time a song is played, its ID is passed through d hash functions. Each function returns a column index, and the cell at (row, column) is incremented by 1. The hash functions are treated as black boxes that spread songs uniformly and independently across columns.

2. Collisions. When two different songs map to the same cell in a row, that cell counts both. Collisions cause overcounting and never undercounting, so every cell is an upper bound on the true count of each song that hashes to it.

3. Query. To estimate how often song x was played, hash it with all d functions, read the d cells and take the minimum. For example, min(8, 6, 6) = 6 is the estimate. The true count is at most 6, and equals 6 when the row holding the minimum has no collision.

4. Memory. The sketch uses a fixed d × w table regardless of how many distinct songs appear, so it needs far less memory than an exact hash map while giving close frequency estimates.
